## Parkora Falcon

A maritime management platform for vessel performance intelligence and operational reporting. Built as a white-label SaaS product with complete isolation between maritime vendor tenants.

<details>
<summary>Technical overview</summary>

<br/>

**Core modules**

- **Voyage Performance Services** — real-time vessel data ingestion, aggregation, and structured reporting pipelines
- **Arrival Report Modules** — automated port arrival documentation with compliance workflow automation
- **Operational Guides** — AI-assisted documentation generation for maritime operations teams
- **Tenant Isolation** — each vendor operates inside a completely isolated data environment, enforced at the database layer via row-level security
- **Role Hierarchy** — Super Admins manage vendor onboarding; Admins manage fleets; Operations staff handle daily data entry

**Architecture highlights**

- Dynamic subdomain routing (`vendor.domain.com`) with per-tenant middleware resolution
- PostgreSQL (Neon) with row-level security policies for hard data boundaries between all tenants
- Global session invalidation propagated simultaneously across all active tenant sessions
- Tailwind v4 with OKLCH-based custom token system enabling full per-vendor visual identity
- Next.js App Router with Server Components optimized for edge performance

</details>

## Principles

These aren't aspirational — they're the working constraints that shape every decision.

1. **Security is architecture, not a layer.** Zero-trust defaults, global session invalidation, and strict server-side validation are structural choices made at the beginning, not retrofitted at the end.

2. **Design precision is a technical requirement.** OKLCH color theory and sophisticated dark mode systems are part of what makes software feel premium and trustworthy — not aesthetic flourishes.

3. **Scalability is designed in, not bolted on.** Multi-tenant schema design, horizontal vendor growth, and edge-ready routing are modeled from day one of any system.

4. **Conversational interfaces over static forms.** AI integration is most powerful when it removes friction from data workflows — not when it exists to check a capability box.

5. **Every abstraction must justify its existence.** Complexity is introduced only when it provides clear, measurable value to the system or to the people using it.
